## Abstract

Self-propagating banking malware can move laterally through reachable hosts faster than a security team can manually isolate every affected system. This project presents a system and method for cost-constrained containment of an Emotet-class banking worm in a simulated bank network. The network is represented as a graph whose vertices are hosts such as workstations, ATMs, branch servers, administrative hosts, and core-banking systems. A discrete-time propagation model records infection growth and arrival information. A composite risk-based containment strategy then selects quarantine targets under a limited action budget by considering propagation urgency, connectivity, and reachable network exposure.

The implementation compares the proposed strategy with no containment, random quarantine, degree-based quarantine, and earliest-observed-infection quarantine. Experiments use two reproducible topologies and 30 trials per configuration. On the 19-node multi-branch topology, the proposed method achieved the lowest mean final infection count: 4.30 nodes, compared with 9.50 without containment and 4.77 for the next-best baseline. On the smaller 8-node topology, the proposed method achieved 2.00 mean infections, tying the degree-based baseline. These results indicate that the method is effective on the larger branching topology, while also showing that its advantage is topology-dependent. The implementation contains 46 automated tests, all of which pass.

**Keywords:** computer networks, lateral movement, banking malware, graph propagation, quarantine, network segmentation, risk score, containment budget.

## 1. Introduction

Banking networks contain several classes of connected systems: employee workstations, branch servers, ATMs, administrative hosts, remote-access gateways, disaster-recovery systems, and core-banking infrastructure. A compromise of one endpoint may allow a self-propagating threat to move laterally through reachable paths. The practical response problem is not only to detect an infection, but also to decide which limited number of systems should be isolated first.

Traditional containment decisions may be reactive, based on alert order, or based on a single graph property such as degree. Those strategies do not combine the current infection state with the structural importance and downstream exposure of each node. This project addresses the following question:

> Given an infected seed node and a limited quarantine budget, which nodes should be isolated, and in what order, to minimize the final number of infected nodes?

The project is framed around an **Emotet-class modular banking worm**. The prototype is a simulation and does not scan, contact, or modify production networks.

### 1.1 Objectives

The objectives are to:

1. Represent a bank network as a graph of hosts and lateral-movement paths.
2. Simulate discrete-time worm propagation from one or more infected seed nodes.
3. Record propagation information that can support containment decisions.
4. Compute a node-level composite risk score using timing and topology information.
5. Select quarantine targets under a fixed action budget.
6. Compare the proposed strategy with four baseline strategies.
7. Produce reproducible metrics, plots, and JSON artifacts for evaluation.

### 1.2 Scope

The system models propagation and containment at node level. It does not implement malware collection, packet capture, vulnerability exploitation, endpoint isolation APIs, or deployment to an actual banking network. Quarantine is represented by removing a node and its incident edges from the simulated graph.

## 2. Background and Problem Statement

An Emotet-class threat is used as the project embodiment because the project requires a specific malware type and because the model concerns self-propagating lateral movement. The simulation abstracts the exact malware implementation into a probabilistic transmission process over network edges. It does not claim to reproduce every operational behavior of Emotet.

The technical problem is constrained containment. Let a network be represented by $G=(V,E)$, where $V$ is the set of hosts and $E$ is the set of reachable lateral-movement paths. Let $S$ be the initially infected seed set, $\beta$ be the per-edge transmission probability, and $K$ be the maximum number of quarantine actions. The goal is to choose an ordered plan $P$ with $|P|\leq K$ such that the final infected set is minimized:

$$
\min_{P,\ |P|\leq K} |I_{final}(G,P,S,\beta)|.
$$

The project therefore focuses on an operator-facing decision: which small number of nodes should receive immediate containment actions.

## 3. Related Approaches and Project Contribution

The prototype compares the following approaches:

| Approach | Decision rule | Limitation addressed by the proposed method |
|---|---|---|
| No containment | Allow propagation without quarantine | Provides the uncontrolled reference |
| Random quarantine | Select random eligible nodes | Does not use network or infection information |
| Degree quarantine | Select highly connected nodes | Ignores current outbreak timing and reachable exposure |
| Earliest infection | Select nodes observed earliest | Does not directly prioritize structural reach |
| Proposed method | Recompute composite risk and greedily quarantine high-risk targets | Combines timing, connectivity, reach, and a finite action budget |

The contribution of this project is an implemented, testable pipeline rather than a claim that one heuristic is universally optimal. The method produces an ordered containment plan and measures its effect under controlled, reproducible trials.

## 4. System Design

### 4.1 Architecture

The implementation is organized into the following modules:

1. **Topology builder:** loads a JSON topology and creates the adjacency graph.
2. **Propagation simulator:** advances infection in discrete steps and records histories.
3. **Risk scorer:** calculates normalized node-level features and a composite score.
4. **Containment optimizer:** applies greedy quarantine actions while budget and growth conditions permit.
5. **Baseline runners:** execute no-containment, random, degree, and earliest-infection strategies.
6. **Comparison and reporting:** runs trials, calculates means and 95% confidence intervals, and saves charts and JSON summaries.

The data flow is:

```text
Topology JSON -> Graph -> Propagation -> Risk features -> Quarantine plan
                                      -> Baseline comparison -> Metrics and figures
```

### 4.2 Network model

The default scenario contains 8 nodes and starts with `WS_1` as the infected seed. The multi-branch scenario contains 19 nodes and starts with `WS_N1`. Node labels identify representative assets such as workstations, ATMs, branch systems, the core system, administrative host, and disaster-recovery host.

An edge indicates that lateral movement is possible in the abstract simulation. The model does not assert that every edge corresponds to a currently permitted production connection.

### 4.3 Propagation model

At each discrete step, an infected node attempts to infect susceptible neighbors with probability $\beta$. The simulator maintains the infected set and records cumulative infection history. Quarantined nodes are removed from the graph together with their incident edges, preventing subsequent simulated transmission through that node.

The model is intentionally lightweight so that the containment policy can be isolated and tested. It is suitable for comparative experiments, not for predicting an actual malware campaign without calibration data.

### 4.4 Composite risk and containment

The proposed strategy combines three normalized signals:

$$
R(v)=\alpha U(v)+\beta_c C(v)+\gamma H(v),
$$

where:

- $U(v)$ is an urgency term derived from infection timing;
- $C(v)$ is a connectivity or centrality term;
- $H(v)$ is the reachable susceptible-node exposure term; and
- $\alpha+\beta_c+\gamma=1$.

The implementation uses default weights $\alpha=0.4$, $\beta_c=0.35$, and $\gamma=0.25$, with a time-decay parameter $\tau=5.0$. At each decision point, the eligible node with the highest score is selected. The action is applied only while the quarantine budget remains and observed per-step growth is above the configured threshold. The outbreak is then allowed to complete so that final infection counts remain comparable between strategies.

The default action budget is $K=2$. This deliberately represents a constrained response team that can isolate only a small number of nodes during the first response window.

### 4.5 Reproducibility controls

The runner supports JSON configuration files and command-line overrides for topology, seed node, transmission probability, action budget, trial count, random seed, and output directory. Independent random generators are used for strategy runs so that comparisons use reproducible seeds. Default and multi-branch artifacts are written to separate result directories.

## 5. Implementation

The implementation is written in Python and uses NetworkX for graph operations and Matplotlib for figures. The main experiment entry point is `src.comparison`. The following files contain the principal implementation:

| File | Responsibility |
|---|---|
| `src/topology.py` | Load and construct network graphs |
| `src/propagation.py` | Simulate discrete-time infection spread |
| `src/risk_score.py` | Compute urgency, centrality, reach, and composite scores |
| `src/containment.py` | Apply budget-constrained greedy quarantine |
| `src/baselines.py` | Execute comparison strategies |
| `src/comparison.py` | Run trials, summarize results, and save artifacts |
| `src/visualize.py` | Generate comparison, infection-curve, and topology plots |
| `tests/` | Automated behavior and correctness tests |

### 5.1 Execution commands

Install dependencies:

```powershell
python -m pip install -r requirements.txt
```

Run the default experiment:

```powershell
python -m src.comparison --config config/default.json
```

Run the multi-branch experiment:

```powershell
python -m src.comparison --config config/multibranch.json
```

Run all tests:

```powershell
python -m unittest discover -v
```

Each configuration writes `comparison_summary.json`, `infection_curves.png`, `network_topology.png`, and `strategy_comparison.png` to its configured output directory.

## 7. Experimental Evaluation

### 7.1 Experimental setup

Both scenarios use a quarantine budget of two nodes and 30 trials. The random seed begins at 42, and each trial uses a reproducible seed sequence. The reported value is the mean final number of infected nodes; the interval is the 95% confidence interval half-width calculated from the trial results.

| Scenario | Nodes | Seed | $\beta$ | Budget | Trials |
|---|---:|---|---:|---:|---:|
| Default | 8 | `WS_1` | 0.25 | 2 | 30 |
| Multi-branch | 19 | `WS_N1` | 0.40 | 2 | 30 |

### 7.2 Default topology results

| Strategy | Mean final infected | 95% CI half-width | Single displayed run |
|---|---:|---:|---:|
| No Containment | 2.60 | 0.80 | 8 |
| Random | 2.27 | 0.57 | 6 |
| Degree | 2.00 | 0.40 | 4 |
| Earliest Infection | 2.10 | 0.48 | 6 |
| Proposed | 2.00 | 0.40 | 4 |

The proposed method ties the degree baseline on the smaller topology. In the displayed run, its ordered plan is `WS_2 -> CORE_1`, reducing the final count from 8 to 4. This result shows that the composite method is competitive, but it does not justify claiming universal superiority.

### 7.3 Multi-branch topology results

| Strategy | Mean final infected | 95% CI half-width | Single displayed run |
|---|---:|---:|---:|
| No Containment | 9.50 | 2.76 | 16 |
| Random | 6.67 | 2.04 | 16 |
| Degree | 5.57 | 1.57 | 13 |
| Earliest Infection | 4.77 | 1.74 | 4 |
| Proposed | **4.30** | **1.14** | 10 |

On the multi-branch topology, the proposed method achieves the lowest mean final infection count. Relative to no containment, the reduction is:

$$
\frac{9.50-4.30}{9.50}\times 100 \approx 54.7\%.
$$

The proposed plan in the displayed run is `CORE_1 -> WS_W2`. The result indicates that combining structural importance with outbreak information can be useful when the topology contains multiple branches and a limited number of actions must be allocated.

### 7.4 Interpretation

The two scenarios provide a balanced result. On a small topology, degree-based selection can be sufficient because the most connected nodes are also obvious bottlenecks. On the larger multi-branch topology, the composite strategy achieves the best average result across 30 trials. The proposed method should therefore be presented as a topology-aware heuristic that improves the evaluated larger scenario, not as a mathematically optimal solution for every possible network.

The confidence intervals overlap between some strategies. The experiments demonstrate comparative behavior in the simulated settings, but they are not a statistical certification of superiority across all banking networks.

## 11. Limitations and Future Work

1. The propagation probability is a simplified abstraction and is not calibrated against a measured Emotet campaign.
2. The current topology files are representative simulation inputs rather than confidential bank network data.
3. Quarantine is simulated by graph removal; a deployment would need SDN rules, firewall ACLs, endpoint isolation, or security-orchestration integration.
4. The greedy selection method is not guaranteed to find the global optimum for arbitrary graphs.
5. The current experiments vary topology and transmission probability but do not provide a full sensitivity analysis over score weights and budgets.
6. The project does not include live traffic, packet capture, vulnerability scanning, or malware execution.
7. Case-study statements and the exact SIH 2026 problem-statement reference require verified external citations before final academic submission.

Future work can include calibrated transmission parameters, larger anonymized topologies, weight and budget sensitivity experiments, a look-ahead or integer-programming selector, and integration with a simulated SDN controller.
